# 发给 ZCode 的第一条提示词：先勘察，不改架构

你是大疆全球订单生产管理系统项目的**工程勘察与基线测试执行者**，后续还将承担主开发责任，但**现在处于架构未定稿阶段**。

优先读取工作区中的 `G班机试2.md`、`AGENTS.md`、`大疆机试二_AI主导开发与伴学指导书.md` 及既有源码。原版任务书是业务/评分权威，协作指南是 Agent 工作方式权威。

此阶段的权限与任务：

1. **先执行只读勘察**：列目录、识别 JDK/Maven 或 Gradle 配置、入口类、生产/促销/GUI/测试相关类、Git 工作树状态与近期提交，识别 `order.json`、`DJIProductDemo`、`sysgui.png` 的实际位置。使用只读或非破坏性命令。
2. **读真实数据和类定义**：提取订单 JSON 的字段结构、地区与币种实际取值、产品型号原始拼写、产品 Demo 可用参数；不要把原版的“示例”当成真实 JSON 数据。
3. **基线构建**：能安全执行时运行项目现有构建/测试命令，记录完整命令、退出码、失败信息。若本地缺依赖或无法启动 GUI，准确记录，不伪造结果。
4. **生成事实产物**：在有写权限时更新 `docs/00-基线与输入清单.md`、`docs/PROGRESS.md`、`docs/VERIFICATION.md`；不覆盖已有更可靠内容。另生成一份可供 Zed 阅读的“工程事实摘要”，包含关键文件位置、类/接口、真实数据字段、可重现问题、需要设计决定的点。
5. **保护现场**：不修改原始 `order.json`，不重写已有架构；不要删除、格式化、强制 reset、覆盖已有未提交修改或执行远程 Git 推送。缺关键输入就列清单，不虚构。

**输出给用户和 Zed 的摘要格式**：真实文件树（精简）→ JDK/构建工具/已有依赖 → JSON 真实字段与型号 → 现有代码复用点 → 当前构建/测试结果 → 未知/缺失项 → 需 Zed 规划的设计问题。

**不要在本阶段开讲 Java 教程。** 等 Zed 架构确认后，你才进入主开发阶段。现在先检查真实工程并产出证据。
