## 二、JSON 事实（已从真实文件提取，非任务书示例）

### 2.1 字段与嵌套结构

```text
[                                    ← 顶层数组（不是包装对象）
  {
    "orderId":      "2025102900001",   ← 字符串，13 位数字，当前 14 笔唯一
    "customerName": "张三",
    "email":        "123@123.com",
    "phone":        "86 13500000001",
    "region":       "CHINA_MAINLAND",  ← 枚举字符串，大写下划线
    "currency":     "CNY",
    "status":       "PENDING",
    "orderDate":    "2025-10-29 15:28:57.638",  ← yyyy-MM-dd HH:mm:ss.SSS
    "totalAmount":  14168,             ← 数值（JSON 中全部为整数）
    "items": [
      {
        "productType": "Mini 4 PRO",   ← 原始拼写，见 2.3
        "quantity":    2,              ← 正整数
        "unitPrice":   5090,
        "totalAmount": 10180           ← 明细金额 = 单价×数量
      }
    ]
  }, ...
]
```

### 2.3 产品型号原始拼写（以 JSON + DJIFactory 常量为准）

| 类别 | JSON 实际型号 | 任务书"型号示例"写法 | 差异 |

### 2.4 金额与数据质量事实

- 全部 14 笔订单：`sum(items.totalAmount) == order.totalAmount` 且 `items.totalAmount == unitPrice × quantity` **全部通过**（脚本逐笔校验）→ 基线数据是"干净数据"；含错误字段/金额的坏文件需自建 fixture（教师验收场景 7 会现场换文件）。
- JSON 中金额全为整数字面量（无小数、无科学计数、无字符串金额）；`sysgui.png` 显示格式为 `CNY 1299.00`（币种代码前缀 + 两位小数，JPY 亦显示两位）。
- **⚠️ 数据陷阱（已实证）**：
  - 订单 `2025102900009` customerName = `\u200cElizabeth Taylor`（**首字符为 U+200C 零宽非连接符**）；
  - 订单 `2025102900010` customerName = `Emil\u200c`（**尾字符为 U+200C**）。
  - 影响：关键字查询、按客户去重/分组、字符串比较时不可见字符会导致"看起来相同"的名字不相等。必须列为设计决定（见 FACTS_FOR_ZED）。
  - `sysgui.png` 截图佐证：截图中该两名客户显示为 "Elizabeth Taylor"、"Emil"，零宽字符不可见。

### 4.2 已知不适配原版要求的实现（现状，不是缺陷）

- 无任何领域模型/服务/GUI/测试代码；无 Git；无 `.gitignore`。
- `DJIProduct` 字段为 `protected` 可变、`weight` 用 `double`（重量非金额，可接受）；金额类字段尚未存在，无违规。
- `getProductCategory()` 返回中文字符串，与任务 1"枚举表示产品类别"需要对齐（保留字符串 API 的同时增加枚举）。
- `DJIFactory.orderDrone` 抛裸 `Exception`，返回值判 `null`——与"明确业务错误"要求需升级为具体异常类型（在不推翻模板的前提下细化）。
