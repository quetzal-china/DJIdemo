# 大疆机试二｜三角色协作启动包

## 当前状态（2026-11-07）

本包**已经准备好协作协议、启动提示词与文档模板**；但**不包含用户本地 Java 基础工程、`order.json`、`DJIProductDemo`、`sysgui.png` 等真实配套素材**，没有编译、测试或 GUI 验收记录。不可将模板中的“计划”认作已完成。

## 工具固定分工

- **Zed**：核心架构师。只读取信息并输出架构蓝图、实施规划与独立审查；不负责教学、不直接做主力编码。
- **ZCode（GLM-5.3-Flash）**：主开发 Agent。真实写代码、编译、测试、修复、维护 Git 状态和阶段交接；无需实时授课。
- **ChatGPT**：伴学导师。用户通过 GitHub 仓库/提交链接或文件提供真实代码时，结合实现讲解知识并帮助用户形成技术建议。
- **用户**：重大业务决策、体验取舍、必要的本地 GUI 验收、GitHub 上传与最终提交。

## 立刻开始：按顺序使用

1. 将本包中的 `大疆机试二_AI主导开发与伴学指导书.md`、`G班机试2.md`、`工作区模板/AGENTS.md` 和 `工作区模板/docs/` **合并**到本地 Java 项目根目录；如果项目已有同名文件，先比较后合并，**不要覆盖原有内容**。`提示词/` 与这份 README 可放在项目外或保留供查阅。
2. 确认本地工程包含老师给的 **真实** `order.json`、`DJIProductDemo` 以及实际基础类。没有的内容先记录缺失，不能让 Agent 虚构。
3. 在 **ZCode** 粘贴 `提示词/01_ZCode_基线勘察_先执行.md`，要求先审计文件、Git 工作树、构建环境与真实输入，只生成基线事实、错误清单和能够复现的初始测试记录。**此时先不大改业务架构**。
4. 将上一步基线报告、必要真实源码及原任务书提供给 **Zed**，粘贴 `提示词/02_Zed_核心架构设计_只规划.md`。Zed 输出规划文本（不负责保存代码）；将结果交给 ZCode **落盘为设计文档**，供你确认重大取舍。
5. 你确认架构（或明确授权按 Zed 推荐缺省方案实施）后，在 **ZCode** 粘贴 `提示词/03_ZCode_全权实施_架构确认后.md`，让它连续执行阶段 2–9。只有真正影响业务输出、结构性变更、破坏性动作才打断你。
6. 重要结构更改或终验前，用 `提示词/04_Zed_最终审查_只报告.md` 调 Zed 生成缺陷清单；交给 ZCode 修复并重新跑测试。
7. 模块完成且你将本地工程推送到 GitHub 后，把**仓库 URL + commit SHA + 模块名称**发给 ChatGPT，或使用 `提示词/05_给ChatGPT_按模块讲解.md`，我会根据真实代码讲解与复审。

## GitHub 上传注意事项

你已选择**自己在本地上传 GitHub**，本包不会替你新建远程仓库或推送。首次上传前检查：是否已有 Git 历史；是否存在未提交的个人改动；`.gitignore`；是否有 Token、密码、个人路径；课程发放的工程/数据是否允许公开。若不确定，优先建立**私有仓库**并仅授权必要访问。

已有本地 Git 仓库时，常用只读检查：

```bash
git status
git log -5 --oneline
git remote -v
git diff --check
```

在确认已有仓库、授权范围与 `.gitignore` 后，再由你决定 `git add`、`git commit`、`git remote add`、`git push` 等操作。不要盲目执行 `git init`、`git push -f` 或覆盖已有远程。

## 什么时候发我 GitHub 链接

推荐选一个独立模块完成节点（例如“领域模型 + JSON 解析”、“抽象工厂 + 序列号”、“促销”、“Stream”、“Swing + EDT”）。同时发送：

```text
仓库：<GitHub URL>
版本：<commit SHA，或者明确写最新 main>
希望讲解的模块：<模块名>
我已有的理解/疑问：<可选>
请结合该版本真实源码与测试结果讲解设计原理，评价技术取舍，并提出一项值得我思考的改进点。
```

如果仓库私有而我无法访问，请使用 GitHub 连接器授权可访问范围，或直接上传相关源文件/项目压缩包。**不能只凭交接文件推断未见过的真实代码。**
